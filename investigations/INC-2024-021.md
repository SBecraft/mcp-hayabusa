# INC-2024-021: LSASS Memory Dump via comsvcs.dll on Finance Workstation

## Summary

"LSASS Memory Dump via comsvcs.dll MiniDump" fired on WS-FINANCE-03. The workstation's user had recently opened an attachment from a phishing email impersonating a vendor invoice; the resulting payload used `rundll32.exe comsvcs.dll, MiniDump` to dump LSASS memory to disk for offline credential extraction.

## Timeline

- **T+0:00** — Phishing email delivered to WS-FINANCE-03's user, subject "Overdue Invoice — Immediate Action Required."
- **T+0:22** — Attachment opened; macro-enabled document drops a secondary payload.
- **T+0:24** — `rundll32.exe` observed invoking `comsvcs.dll` with a MiniDump argument against `lsass.exe`; alert fires.
- **T+0:31** — SOC isolates WS-FINANCE-03 from the network.
- **T+2:15** — Forensic review confirms the dump file was written to a temp directory but not observed leaving the host before isolation.

## Root Cause

Phishing email bypassed the email gateway's attachment filtering because the macro payload used a delayed-execution technique to evade sandboxing. The user was not the intended high-value target directly, but their workstation has wire-transfer-approval access, making it a valuable credential target.

## Impact

No confirmed exfiltration of the dump file before containment, but the account's password and the local machine's credentials were treated as compromised out of caution. No fraudulent wire transfers were traced to this incident.

## Remediation

1. Rotated the affected user's domain credentials and any locally cached credentials on WS-FINANCE-03.
2. Rebuilt WS-FINANCE-03 from a known-good image.
3. Updated email gateway rules to catch the delayed-execution macro technique used in this campaign.

## Lessons Learned

- High-value-access workstations (wire-transfer approval, in this case) warrant tighter application allow-listing than the general workstation fleet, given they're attractive credential-dump targets even without being "sensitive" in the traditional server sense.
- comsvcs.dll-based LSASS dumping remains an effective living-off-the-land technique; detection coverage for it should be validated regularly.
