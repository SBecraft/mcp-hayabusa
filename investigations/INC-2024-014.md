# INC-2024-014: DCSync Detected Against Primary Domain Controller

## Summary

The "DCSync - Directory Replication Services Used to Dump Credentials" alert fired for DC1.insecurebank.local. Investigation confirmed a compromised service account (`svc-backup-legacy`) was used to issue DS-Replication-Get-Changes / DS-Replication-Get-Changes-All requests against the domain controller from a non-DC host, consistent with Mimikatz's `lsadump::dcsync`.

## Timeline

- **T+0:00** — `svc-backup-legacy` authenticates to FS1.insecurebank.local via a scheduled task that had been modified two days prior (outside the change window).
- **T+0:14** — DCSync-shaped EventID 4662 requests observed against DC1, originating from FS1, using `svc-backup-legacy`'s credentials.
- **T+0:15** — Alert fires; SOC begins triage.
- **T+1:02** — `svc-backup-legacy` password reset; FS1 isolated pending forensic review.
- **T+3:40** — Forensic review confirms the scheduled task on FS1 was the initial foothold; root cause traced to an unpatched file-sharing service exploited two days earlier.

## Root Cause

`svc-backup-legacy` was over-privileged (had been granted Replicating Directory Changes rights years earlier for a backup tool that was later decommissioned, but the permission was never revoked). This over-privileging turned a file-server compromise into a domain-wide credential exposure risk.

## Impact

DCSync request succeeded before containment; all domain account hashes, including `krbtgt`, were potentially exposed. A full `krbtgt` password reset (performed twice) and a broad credential rotation were required.

## Remediation

1. Removed Replicating Directory Changes rights from `svc-backup-legacy` and audited all other accounts for the same stale over-privileging.
2. Rotated `krbtgt` password twice to invalidate all outstanding Kerberos tickets.
3. Patched the file-sharing vulnerability on FS1 that provided initial access.

## Lessons Learned

- Directory-replication rights should be reviewed on a recurring schedule, not granted-and-forgotten.
- Service accounts tied to decommissioned tooling need an offboarding checklist, not just a password that never gets checked again.
